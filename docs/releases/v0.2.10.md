# Frontier Decision Engine v0.2.10

Frontier Decision Engine v0.2.10 is the final pre-publication delivery release for the first controlled GitHub launch.

- **Windows manifest-path correction:** the manifest builder uses `fileURLToPath()` rather than URL `.pathname`, preserving valid drive-letter paths in Git Bash and Windows Node.

## Highlights

- Decision-first DMDU workflow with XLRM framing, plural non-probabilistic futures, strategy-specific stress testing, critical-objective gating, adaptive pathways, and mandatory human rationale.
- Open Phenomenon Verification profile with local hashing, transparent calibration and measurement, Evidence Level 0–2 controls, and portable JSON/HTML exports.
- Public-safe morphology, experience, and reference datasets with strict evidence-class and privacy boundaries.
- **49 automated Node tests** plus repository validation, six browser modes, accessibility/reflow/forced-colors/PDF checks, and deterministic release packaging.
- Live GitHub Pages end-to-end verification against the deployed HTTPS URL before the Pages workflow can complete.
- GitHub-verified signed annotated tag enforcement before release publication.
- Repository release immutability required and checked before the tag workflow publishes.
- Deterministic ZIP and checksum attestations, release-level verification, and verification of both hosted assets.
- Immutable official GitHub Actions pins, lockfile-based npm installation, disabled package-manager caching, cross-platform LF normalization, Dependabot coverage, and a public-boundary PR template.

## Maturity boundary

This is a public reference implementation for education, collaboration, methodology review, partner demonstrations, and pilot design. Scores are analyst inputs rather than probabilities. Machine output is advisory. The project is not a predictive engine, a full RDM/MoRDM ensemble, scientific proof of phenomenon origin, or a sole basis for irreversible decisions.

## GitHub delivery assurance

The immutable-release precheck uses the protected `RELEASE_ADMIN_TOKEN` environment secret with repository Administration: read. After publication, the workflow downloads both hosted assets into a clean directory and verifies their checksum, release attestation, release-asset attestations, and build-provenance attestations.
